# 強化学習エージェントの学習方針

## 1. エージェントに渡すデータ（状態空間 / Observation Space）

Python側のニューラルネットワークに渡すため、C++側で毎ステップ生成すべきデータの塊（テンソル化される情報）です。

* **① 数値ステータス (Numerical State):**
    * 自分と相手の基本情報（正規化されたHP、MP、お金）。
    * 状態異常フラグ（Multi-hotベクトル）。
    * **【重要】** `remaining_damage`（現在飛んできているダメージ量 − 仮置き防具の合計値）などの、C++側で計算済みのサポート数値。


* **② 現在のカード情報 (Card State):**
    * `hand_cards`: 現在の手札のカードID（最大18枠。空きは `0` でパディング）。
    * `staged_cards`: 現在「仮置き場」にセットされているカードIDの配列。


* **③ イベント履歴 (Event History):**
    * 過去 $N$ 回分（例: 20回分）のゲーム内イベントのログ構造体配列。
    * 各要素は `[実行者, フェーズ, 行動種別, カードID, 確定ダメージ等]` を持つ。


* **④ 合法手マスク (Action Mask):**
    * 長さ19の `[0, 1]` の配列。次に選択可能な行動のみ `1`、ルール違反の行動は `0`。



## 2. エージェントの行動一覧（行動空間 / Action Space）

AIの出力層は、以下の19次元の離散値（Discrete）に完全に固定されます。キャンセルという概念はありません（Forward-Only）。

* **`0 ～ 17`:** 手札のインデックス（$i$ 番目のカードを仮置き場にセットする）
* **`18`:** 確定（Submit）

## 3. 学習と進行の仕組み（マイクロステップ）

1ターンを「1枚のカード選択」という微小なステップに分解し、C++とAIがキャッチボールをして進めます。

1. **AIの推論:** 渡されたデータとマスクを元に、19個の選択肢から1つを選ぶ。
2. **C++の状態更新 (カード選択時):**
    * 選ばれたカードを手札から「仮置き場」に移動させる。
    * 次に重ねることが可能なカードと「確定」のみが `1` になるよう、**アクションマスクを再計算**する。


3. **C++の処理解決 (確定選択時):**
    * 仮置き場のカード効果をすべて計算し、**乱数（確率的効果）を振って結果を確定**させる。
    * HPや手札を増減させ、起きた出来事を「イベント履歴」の末尾に追記する。
    * 相手のターン（防御フェーズなど）へ移行する。


4. **報酬の付与:**
    * ゲーム終了時に勝者 `+1`、敗者 `-1`（または ±100 など）を与える。
    * 中間報酬（HP変動など）は与えず、ネットワークの「補助タスク（次ターンのHP予測、相手手札予測）」で学習を補助する。

## 4. 環境が提供すべき C++ API インターフェース

C++の環境クラス（Pybind11でラップする対象）は、OpenAI Gym (Gymnasium) に似た、以下のシンプルなAPIメソッドを提供できれば完璧です。

* **`reset(int seed)`**
    * 指定された乱数シードでゲームを初期化し、最初の状態を返す。
    * ※運の相殺（Duplicate Evaluation）を行うため、シードの指定機能は必須です。


* **`step(int action)`**
    * AIからの行動（0〜18）を受け取り、ゲームを1マイクロステップ進める。
    * 戻り値として `(次の状態, 報酬, ゲーム終了フラグ)` を返す。


* **`get_states_buffer()`** *(極限効率化用)*
    * マルチスレッドで動作している全数万ゲームの状態構造体配列のポインタを返し、Python側にゼロコピーでNumPy配列として覗かせる。

## 5. C++環境実装で求められる絶対要件

これからC++で実装を進める上で、後々のボトルネックやバグを防ぐための最重要ポイントです。

* **Trivially Copyable なデータ構造**
    * 盤面状態やイベント履歴の構造体には、`std::string` や仮想関数 (`virtual`) 、ネストされたポインタを含めないでください。すべて固定長の配列（`int cards[18]` など）とプリミティブ型で構成し、`std::memcpy` で一気にコピーできるようにします。


* **厳密なルール・ステートマシン**
    * 「アクションマスクの生成」がこのAIの命綱です。「今は攻撃フェーズの1枚目」「今は防御フェーズで、相手は属性攻撃をしてきている」といったゲームの進行状態（ステート）を厳密に管理し、絶対にルール違反の行動が `1`（選択可能）にならないように実装を徹底します。


* **算数と確率のオフロード**
    * AIに計算をさせないでください。防具による残りダメージ計算はC++で行い状態として渡し、確率的なカードの効果もAIが「確定」した直後にC++でサイコロを振り、その結果を事後報告としてイベントログに書き込みます。
