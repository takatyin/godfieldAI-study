# GodField Event Log & History Specification

強化学習AIエージェントの Observation 入力およびビジュアライザ・リプレイ用のイベントログ構造に関する仕様書です。

## 概要
GodFieldのゲーム進行中に発生する主要なプレイヤー行動（カード仮置き、攻撃確定、防御確定、カード廃棄等）および自動ゲームイベント（守護神の行動発動、病発作、超常現象、反射・弾き等）を構造化された `GameEvent` オブジェクトとして記録します。

`InternalState` 内にリングバッファとして保持され、観測時 (`get_observation`) に観測プレイヤーの視点に合わせた正規化（プレイヤーIDのXOR変換および非公開手札/山札カードIDのマスキング `0`）が適用されます。

---

## 1. データ構造と記録方針

### 主要なイベント種別 (EventType)
* **`STAGE_CARD` (1)**: 手札からのカード仮置き（攻撃・防御・捨てる対象の配置）。
* **`CONFIRM_ATTACK` (3)**: 攻撃・奇跡・雑貨の使用確定。
* **`CONFIRM_DEFENSE` (4)**: 防御確定 (合計ガード値 `value`)。
* **`PASS_DEFENSE` (5)**: 防御スルー (ガードなし被弾)。
* **`ATTACK_HIT` (6) / `ATTACK_MISS` (7)**: 命中判定の結果。
  - **命中判定が実際に行われた攻撃でのみ配信されます。** すなわち
    - 命中率100%未満のカードを含む攻撃（例: つるシュート、火星神の炎の叫び、昇天弓）
    - 全体攻撃（武器・奇跡とも）
    が対象です。
  - 命中率100%の単体攻撃（例: パンチ、＜火の玉＞）では配信されません。当たることが
    確定しているため「当たった／外れた」を伝える必要がないためです。被弾量は
    `TAKE_DAMAGE` で配信されるので、ダメージ表示には影響しません。
  - `card_id` は攻撃元カード、`value` は `ATTACK_HIT` のとき攻撃力、`ATTACK_MISS` のとき `0.0f`。
* **`EFFECT_SICKNESS` (8)**: 病気による症状（ダメ/回復）および悪化・発作イベント。
  - `value` には `SicknessEvent` ビットマスク値（C++ / Python 共通定数）が格納されます：
    - 下位4ビット (`0x0F`): 病気種別 (`TYPE_NONE=0`, `TYPE_COLD=1`, `TYPE_FEVER=2`, `TYPE_HELL=3`, `TYPE_HEAVEN=4`)
    - フラグビット: `FLAG_DAMAGE = 16` (ダメ), `FLAG_HEAL = 32` (回復), `FLAG_WORSENED = 64` (悪化), `FLAG_SEIZURE = 128` (発作)
  - ※ 悪化発生時は「悪化イベント (`FLAG_WORSENED`)」と、その直後に「悪化後の症状イベント (`FLAG_DAMAGE` / `FLAG_HEAL`)」の2つが連続して配信されます。
* **`EFFECT_GUARDIAN` (9)**: 守護神の行動発動。
  - `card_id`: 守護神の技・スキルの仮想カードID (`ID_FIRE_SHOUT`, `ID_HAIL`, `ID_HEALTHY_SEAFOOD_SOUP` 等)。
  - `value`: 守護神ID (1: 火星神, ..., 10: 月神)。
  - `target_id`: 対象プレイヤー。
* **`REFLECT_DAMAGE` (10) / `BOUNCE_ATTACK` (21) / `BLOCK_ATTACK` (20)**: 反射（ダメージ）・弾き・阻止の発動（`value = 0.0f`。実際に適用された被弾量は後続の `TAKE_DAMAGE` にて記録されます）。
* **`REFLECT_MIRROR` (23)**: スーパーミラーによる対象反転発動（売る・買う・雑貨等の非ダメージ反射）。
* **`TAKE_DAMAGE` (11)**: 戦闘・病気によるダメージ適用。
* **`INSTANT_DEATH` (28)**: 闇属性攻撃による即死（防御力を貫通してHPが0になる）。
  - ダメージ自体は先行する `TAKE_DAMAGE` に記録されます。闇属性の即死ではその
    ダメージ量と実際のHP減少量が一致しないため、`TAKE_DAMAGE` だけでは
    「なぜHPが0になったか」を履歴から復元できません。そのため別イベントとして記録します。
  - 虹のカーテンで防いだ場合は配信されません。
* **`REVIVE` (29)**: 太陽のお守りによる復活（`card_id` は太陽のお守り、`value` は復活後のHP）。
  - HPが0になった直後に静かに10へ戻るだけなので、記録しないと履歴からは何も起きて
    いないように見えます。お守りが何枚消費されたかも追えません。
  - 死亡判定は解決ステップの終わりに1回だけ行われるため、**1回の攻撃に対してこの
    イベントは高々1つ**です（連撃は1発ごとに独立した攻撃なので、1発ずつ配信されます）。
    詳細は `rules.md` 7章「1回の攻撃の解決順序」。
* **`BUY_CARD` (14) / `SELL_CARD` (15) / `EXCHANGE` (16)**: 取引・売買・両替イベント。
* **`DISCARD_CARD` (18)**: 手札からのカード破棄確定 (`card_id` に破棄した実カードIDを保持)。
* **`GUARDIAN_ENTER` (25)**: 守護神降臨・召喚（`value`: 降臨した守護神ID `1`〜`10`）。
  - ※ 【守護の壺】の使用や超常現象【日食】によって宿る際に配信されます。
* **`GUARDIAN_LEAVE` (26)**: 守護神の退散・消滅（`value`: 退散した守護神ID `1`〜`10`）。
  - ※ 被弾時の10%確率での退散、および【日食】・守護封印のつぼ・奇跡【解放】など新規召喚によって上書き（交代）される際に配信されます。
* **`EFFECT_SICKNESS` (8)**: 病気の状態変化・症状。
  - `value` には `SicknessEvent` ビットマスク値が格納されます：
    - 下位4ビット (`0x0F`): 病気種別 (`TYPE_COLD=1` (風邪), `TYPE_FEVER=2` (熱病), `TYPE_HELL=3` (地獄病), `TYPE_HEAVEN=4` (天国病))
    - フラグビット: `FLAG_DAMAGE = 16` (症状によるダメージ), `FLAG_HEAL = 32` (天国病によるHP回復), `FLAG_WORSENED = 64` (発症・悪化), `FLAG_SEIZURE = 128` (天国病の発作による死亡), `FLAG_CURED = 256` (治癒)
  - `FLAG_CURED` の場合、種別には**治る前の病気**が入ります。何が治ったのか分からないと履歴として意味がないためです。
* **`EFFECT_CURSE` (27)**: 呪い状態変化（付与・解除・自然消滅等）。
  - `value` には `CurseEvent` ビットマスク値が格納されます：
    - 下位4ビット (`0x0F`): 呪い種別 (`TYPE_FOG=1` (霧), `TYPE_FLASH=2` (閃光), `TYPE_DARK_CLOUD=3` (暗雲), `TYPE_DREAM=4` (夢))
    - フラグビット: `FLAG_APPLIED = 16` (付与), `FLAG_CLEARED = 32` (解除)

## 2. 視点正規化と非公開情報マスキング

Observation 生成時 (`get_observation(state, observer_id)`):
1. **Actor / Target の正規化**:
   - `observer_id` を基準として、`actor == observer_id` の場合は `0` (自分)、それ以外は `1` (相手) に反転。
   - `target_id` も同様に反転。
2. **非公開カードのマスキング**:
   - 相手が手札から仮置きした段階で、まだ確定（`confirm_card`）していないカードや公開されていないカードIDは `card_id = 0` (裏向き/非公開) に置き換えて出力。
   - 確定（攻撃確定、防御確定、使用、破棄）した時点で、実際の `card_id` が記録されたイベントが出力されます。

## 3. 「捨てる (Discard)」アクションのイベントシーケンスとルール

「捨てる」アクションは、攻撃や防御と同じく「仮置き (`STAGE_CARD`) ➔ 確定 (`DISCARD_CARD`)」の統一イベントモデルに従って記録されます。

### イベント発生シーケンス

| 順序 | 操作 / 状況 | イベント種別 (`EventType`) | フィールド値 (`card_id`, `target_id`) | ビジュアライザテキスト表現 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | メインフェイズで「捨てる」を選択 | `STAGE_CARD` (1) | `card_id = -1`, `target_id = -1` | `自分 置いた 【捨てる】` |
| **2** | 捨てたいカードA（例: 革の服）を選択 | `STAGE_CARD` (1) | `card_id = 115` (革の服), `target_id = -1` | `自分 置いた 【革の服】` |
| **3** | 捨てたいカードB（例: 鉄の兜）を選択 | `STAGE_CARD` (1) | `card_id = 116` (鉄の兜), `target_id = -1` | `自分 置いた 【鉄の兜】` |
| **4** | 「決定（確定）」ボタンを押す | `DISCARD_CARD` (18)<br>`DISCARD_CARD` (18) | `card_id = 115`, `target_id = 0`<br>`card_id = 116`, `target_id = 0` | `自分 【革の服】 を捨てた`<br>`自分 【鉄の兜】 を捨てた` |

### イベント発生・ログ出力ルール

- 手札からカードを選択して捨てるフェイズでは、選択ごとに `STAGE_CARD` イベントが発行されます。
- 「確定」ボタンを押すと、捨てられた各カードの `DISCARD_CARD` (EventType 18) イベントが発行されます。
- 確定後に Observation を取得した時点で、一連のイベントログ（`置いた 捨てる`, `置いた 革の服`, `革の服 を捨てた` 等）が取得されます。

## 4. 「買う (Buy)」アクションのイベントシーケンスとルール

「買う」（ID: 1）は、相手または自分からランダムに提示されるカードを購入（あるいは見送り）する取引アクションです。

### イベント発生シーケンス（対相手）

| 順序 | 操作 / 状況 | イベント種別 (`EventType`) | フィールド値 (`card_id`, `target_id`, `value`) | ビジュアライザテキスト表現 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 「買う」カードを選択 | `STAGE_CARD` (1) | `card_id = 1` (買う), `target_id = -1` | `自分 置いた 【買う】` |
| **2** | 「相手を対象」を選択 | `CONFIRM_ATTACK` (3) | `card_id = 1`, `target_id = 1` (相手) | `自分 敵へ 【買う】 を使った` |
| **3** | 相手が受諾 | *(内部処理)* | 相手の手札から1枚選ばれ公開 | *(画面に提示カードと価格表示)* |
| **4a** | 自分「買う (`ACTION_DEAL_YES`)」選択 | `BUY_CARD` (14) | `card_id = 提示カードID`, `target_id = 1`, `value = 価格` | `自分 敵から 【革の服】 を ¥10 で買った` |
| **4b** | 自分「断る (`ACTION_DEAL_NO`)」選択 | `REFUSE_DEAL` (19) | `card_id = 提示カードID`, `target_id = 1`, `value = 0` | `自分 敵からの 【革の服】 を買わなかった` |

---

## 5. 「売る (Sell)」アクションのイベントシーケンスとルール

「売る」（ID: 0）は、「売る」カードと「売りつける商品」の2枚をセットで手札から選択し、相手へ強制的に売却するアクションです。

### イベント発生シーケンス（対相手）

| 順序 | 操作 / 状況 | イベント種別 (`EventType`) | フィールド値 (`card_id`, `target_id`, `value`) | ビジュアライザテキスト表現 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 「売る」カードを選択 | `STAGE_CARD` (1) | `card_id = 0` (売る), `target_id = -1` | `自分 置いた 【売る】` |
| **2** | 商品（例: 鉄の剣）を選択 | `STAGE_CARD` (1) | `card_id = 1` (鉄の剣), `target_id = -1` | `自分 置いた 【鉄の剣】` |
| **3** | 「相手を対象」を選択 | `CONFIRM_ATTACK` (3) | `card_id = 0`, `target_id = 1` (相手) | `自分 敵へ 【売る】 を使った` |
| **4** | 相手が確定（受諾） | `SELL_CARD` (15) | `card_id = 1` (鉄の剣), `target_id = 1`, `value = 価格` | `自分 敵へ 【鉄の剣】 を ¥15 で売った` |

※ 買い手（相手）は代金を拒否できず、所持金 ➔ MP ➔ HP（直接ダメージ）の優先順位で強制支払いが発生します。

## 6. スーパーミラー反射 (`REFLECT_MIRROR`)

「売る」「買う」「雑貨」などの非ダメージ行動に対して相手が【スーパーミラー】を発動した場合、`REFLECT_MIRROR` (23) が発行され、アタッカーとディフェンダー（売り手と買い手 / 発動者と対象）が逆転して進行します。

| 順序 | 操作 / 状況 | イベント種別 (`EventType`) | フィールド値 (`card_id`, `target_id`) | ビジュアライザテキスト表現 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 相手がスーパーミラーを選択 | `REFLECT_MIRROR` (23) | `card_id = 126` (スーパーミラー), `target_id = 0` (自分) | `敵 【スーパーミラー】 で跳ね返した！` |
| **2** | 取引対象が反転して進行 | `SELL_CARD` (15) / `BUY_CARD` (14) | 反転した結果の取引パラメータ | `敵 自分から 【鉄の長剣】 を ¥10 で買った` 等 |

## 7. 指輪の反撃・防御効果 (`RING_EFFECT`)

防御時に各種指輪（`ID_MARS_RING` 〜 `ID_VENUS_RING`）が発動した場合、専用イベント `RING_EFFECT` (24) （`value = 0.0f`）が配信されます。

※ 【反射剣】や月光シリーズ（【月光のオノ】【月光のかぶと】【月光の盾】【月光のよろい】）による跳ね返しは `REFLECT_DAMAGE` (10) として区別されます。

| 指輪 | 発動効果 | イベント種別 (`EventType`) | フィールド値 (`card_id`, `value`) | ビジュアライザテキスト表現 |
| :--- | :--- | :--- | :--- | :--- |
| **土星・火星・水星・木星・天王星・冥王星・金星の指輪** | カウンター攻撃・呪い付与・CP奪取 | `RING_EFFECT` (24) | `card_id = 各指輪ID`, `value = 0.0f` | `敵 【土星の指輪】 の反撃が発動！` |
| **海王の指輪** | 貫通ダメージの2倍の自分のMPを増加 | `RING_EFFECT` (24) | `card_id = 184` (海王の指輪), `value = 0.0f` | `自分 【海王の指輪】 の反撃が発動！` |

## 8. ビジュアライザでの利用

`visualize_server.py` は C++ から取得した `Observation.history` を日本語テキストおよび JSON イベントオブジェクトに変換してフロントエンドに提供します。
守護神行動の技名（`【炎の叫び】`等）、捨てたカード名（`【革の服】`等）、病気悪化・発作ログ、指輪の反撃ログ（`【土星の指輪】 の反撃が発動！`等）がリアルタイムにログ表示されます。
