# GodField Game Logic Implementation Roadmap

ゴッドフィールドの複雑なルールを破綻なく実装するための、7フェーズの段階的ロードマップ。
AIポリシーや既存の `game_flow.md` に囚われず、C++側で最適な状態遷移（ステートマシン）と内部状態（InternalState）を独自に設計しながら進める。

## Phase 1: 基礎インフラと自己完結アクション（回復と祈る）
最も単純な処理から実装し、ターン遷移の基本ループを作る。
- **対象機能**: 
  - 祈る（山札からのドロー）：手札に `is_weapon` が1枚もない場合のみ使用可能。
  - 回復アイテム（自分・相手への使用）。
- **状態管理のポイント**:
  - 複数枚使用を考慮し、使用したカードは直ちに消さず、手札内で `used` フラグを立てて管理する。ターン終了時に `used` のカードを補充（ドロー）する。
  - 回復アイテムを相手に使った場合、本来は「スーパーミラー」の割り込みステップが発生するが、Phase 1ではミラーは未実装とし、直接効果を解決する。

## Phase 2: 基本的な物理戦闘（殴り合いと防御）
攻撃と防御の基本フローを作る。属性、反射、状態異常はまだ入れない。
- **対象機能**: 
  - 無属性の武器（単体・複数枚出し）による攻撃。
  - 無属性の防具による防御。
- **状態管理のポイント**:
  - 攻撃プラスや防御において、「どのカードをどの順番で出したか」が重要になるケースがあるため、出したカードの履歴（または順番）をState上で追跡可能にする。
  - 反射（弾く/反射）はPhase 5まで実装しない。単純に受けるか、防御力で軽減/ブロックするのみ。

## Phase 3: 属性（Element）と状態異常（Status Ailments）
Phase 2の戦闘に属性相性と状態異常を乗せる。
- **対象機能**: 
  - 武器・防具の属性対応（火属性の攻撃には火・水防具のみ、といったAction Maskの制約）。
  - 虹のカーテン（属性無視防御）。
  - 攻撃ヒット時の状態異常（霧、閃光、暗雲、夢）の付与と、ターン終了時の継続ダメージ処理。

## Phase 4: 奇跡（Miracle）と魔法防御
物理攻撃とは独立した状態遷移を持つ「奇跡」システムを実装する。
- **対象機能**: 
  - 奇跡の使用とMP消費。
  - 奇跡のプラス（コスト0カードの適用など）。
  - 奇跡に対する「阻止」（※反射はPhase 5へ回す）。

## Phase 5: イベントスタックと複雑なカウンター（反射・指輪・昇天弓）
**最大の難所。** 状態遷移の途中で別のアクションが割り込む処理を「イベントスタック（キュー）」で解決する。
- **対象機能**: 
  - 武器・奇跡の「弾く / 反射」の実装（対象が移り変わる再帰的な処理）。
  - 防御時の「指輪」解決（防御した結果、相手に攻撃や状態異常が飛ぶ）。
  - 死亡時の「昇天弓」追撃処理、「太陽のお守り」蘇生。
  - スーパーミラー（Phase 1の雑貨や取引などへの割り込み）。

## Phase 6: 取引と経済（経済フェイズ）
お金（Money）の概念と、相手とのインターフェースを拡張する。
- **対象機能**: 
  - 取引（売る、買う、両替、捨てる）。
  - お金が足りない場合の代替消費（MP → HP）。HPが0になっても太陽のお守りがあれば蘇生する処理。
  - `is_known_to_opp` (相手にバレているカード) のフラグ管理。

## Phase 7: 守護神と病（レアメカニクス）
ターンの開始時にランダム性をもたらす要素を実装する。
- **対象機能**: 
  - 守護神フェイズのランダム行動。
  - 病（風邪、熱病、地獄病、天国病）の感染と発作ダメージ。

---
**特記事項**:
- HPやMPの増減時、一時的に0になっても同フェイズ内で回復すれば生存するケース（例: HP5でHP吸収15ダメージの武器を自分に使うと、HP5 -> HP0 -> HP15 となり生存）に留意してダメージ/回復スタックを設計すること。
