# 強化学習ハイパーパラメータ探索 (Optuna) 実験レポート

## 1. 実験の目的
本実験の目的は、GodField の C++ 並列シミュレーション環境において、強化学習エージェント（PPO）がゲームの基礎ルールと基本戦術を最も効率よく学習できるハイパーパラメータを特定することである。
自己対戦（Self-Play）環境では評価軸（相手の強さ）が変動してしまい純粋な学習効率の測定が困難なため、ここでは固定のヒューリスティックAI（`HeuristicOpponent`）に対する勝率を目的関数とし、GPU効率と学習効率（更新回数）のベストバランスを探る。

## 2. 実験環境 (Hardware & Setup)
* **実行環境**: 学習用サーバー (`istanbul02`)
* **CPU**: AMD EPYC 7452 32-Core Processor
* **GPU**: NVIDIA RTX 3090 × 4 (Optuna マルチGPU分散処理)
* **OS**: Linux (Ubuntu 22.04)
* **シミュレータ**: C++ カスタム環境 (OpenMP利用) + `GodFieldVectorEnv`
* **並列環境数**: 1000 parallel environments

## 3. 探索手法 (Methodology)
* **最適化フレームワーク**: Optuna (SQLite バックエンドによる4並列ワーカー実行)
* **アルゴリズム**: MaskablePPO (sb3-contrib)
* **評価基準 (Objective)**: `HeuristicOpponent` と 1,500,000 タイムステップ対戦し、直近の評価インターバルにおける勝率（`win_rate`）を最大化する。
* **早期打ち切り (Pruning)**: `MedianPruner(n_warmup_steps=1)`
  * 各トライアルは学習を4つのインターバルに分け、勝率が過去の中央値を下回っている見込みのないトライアルは即座に計算を打ち切り（Pruned）、リソースを節約した。
* **試行回数**: 各GPU 10トライアル × 4GPU = 合計 40 トライアル

## 4. 探索空間 (Search Space)
以下の7つのパラメータに対して、Optunaを用いた探索を行った。

| パラメータ名 | 探索範囲 / 候補 | 意味・役割 |
| :--- | :--- | :--- |
| `batch_size` | `[8192, 16384, 32768, 65536]` | 1回の勾配更新に使うデータ数。ハードウェア処理効率と勾配のノイズ幅のトレードオフ。 |
| `n_steps` | `[256, 512, 1024, 2048]` | 1環境あたり何手先まで進めてから学習を行うか。 |
| `n_epochs` | `[2, 4, 8, 10]` | 集めたデータを何周回して学習するか。過学習とサンプル効率のバランス。 |
| `learning_rate`| `Log-Uniform [1e-5, 1e-3]` | 学習率。 |
| `ent_coef` | `Log-Uniform [1e-4, 5e-2]` | エントロピー係数。高いほどランダムな行動（探索）を促す。 |
| `clip_range` | `[0.1, 0.2, 0.3]` | PPOの更新幅の制限。 |
| `gamma` | `[0.99, 0.995, 0.999]` | 割引率。どれだけ遠い未来の報酬を重視するか。 |

## 5. 実験結果 (Results)
合計40回のトライアルのうち、過半数が `MedianPruner` によって早期打ち切りされ、非常に効率的に探索が完了した（総所要時間：約20分）。
最後まで学習を完遂したトライアルの中で、最も高い勝率を記録したトップモデルは **勝率 73.3%** を達成した。

## 6. 考察と今後の展望 (Conclusion & Next Steps)
本実験から以下の知見が得られた。

1. **バッチサイズのスイートスポット**: 
   RTX 3090の計算資源を埋めるため `32768` などの超巨大バッチサイズも有力候補であったが、最終的には `16384` が選定された。これはGPUを適度に回しつつも、「勾配更新回数を稼いで早く賢くなる」というディープラーニング本来の学習効率を優先した結果と言える。
2. **小刻みなロールアウトと深い反復**:
   `n_steps` が最小の `256` 、`n_epochs` が最大の `10` という結果になった。これは「少しずつゲームを進めて（256手）、その直近の経験を限界まで（10回）復習する」という学習スタイルが、ヒューリスティックAIに対する適応を最速化することを示している。
3. **エントロピーの扱い**:
   最適化された `ent_coef` は約 `0.0025` と比較的低めであった。これは「決まった行動をするAI（HeuristicOpponent）の隙を突く」という固定目標においては、過度な探索を控えて最適解を素早く搾取する方が勝率が高まるためと考えられる。

### 次のフェーズへの適用
今回の探索結果は、「GodFieldのルールを最速でネットワークに叩き込むための最適化・ハードウェア限界」を証明した。
次フェーズである「自己対戦 (Self-Play)」においては、今回得られた `batch_size`, `n_steps`, `learning_rate` などのベースラインを引き継ぎつつ、相手が未知の手を打ってくる環境下での局所解陥落を防ぐため、**意図的に `ent_coef` (エントロピー) を少し高めに設定** するなど、本番に向けた微調整を行っていく。
